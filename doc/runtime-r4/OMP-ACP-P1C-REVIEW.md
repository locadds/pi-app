## 首轮发现与处理

### 1. 普通文件审批早于结构化 tool call

首轮审查担心审批逻辑解析人类可读文字。真实 OMP 18.1.2 追踪与固定上游源码核对后确认：普通 `edit/write` 的 `elicitation/create` 确实发生在后续结构化 `tool_call` 之前，宿主无法先取得 toolCallId。

处理结果：保留 ACP 原生 `session/request_permission` 作为优先路径；只为固定 `omp-18.1.2-v1` 增加窄兼容 envelope。它只接受精确 form schema、单个 `edit/write` 目标和安全相对路径；多目标、歧义、截断、控制字符、错误会话、未知工具或未来形状全部取消。TaskHub 仍重新核验 Attempt 工作树和文件清单，解析器本身无权批准。

复审结论：固定版本兼容层可接受，无代码阻断；OMP 升级前必须重新 Spike。

### 2. 真实模型证据不可复查

首轮代码审查能复跑聚焦测试，但使用了不含传递依赖和 `pi_natives` 的主包子树，无法复现真实 4/4；当时文档也只有占位路径。

处理结果：新增 `OMP-ACP-P1C-REAL-SMOKE.md`，保存最终复跑时间、真实原始输出、退出码、精确 D 盘完整依赖图位置、主包/入口/树指纹和非敏感模型配置指纹。复审确认 `dist/cli.js`、`@oh-my-pi/pi-natives`、包名版本、摘要、3,136 个文件和 48,326,575 字节均一致。

复审结论：真实证据阻断已解除；代码质量 `APPROVE`。

### 3. PATH 同版本是否可能绕过受信安装

处理结果：生产装配测试显式开启候选接缝，断言先消费 trusted installation inspection，使用回执派生的固定入口，并令 PATH OMP probe 一旦被调用就失败。缺少有效回执时不创建进程。

复审结论：通过。

### 4. 真实模型与 Delivery 证据口径

处理结果：QA 明确拆分两段证据。真实 OMP 子进程证明权限、实际工作树修改、Diff、主机结果摘要和恢复绑定；确定性集成测试再证明同一摘要进入 CandidateAudit、ChangeSet 和 Delivery。没有声称一个真实供应商会话已经连续执行到最终人工应用。

复审结论：接受该聚焦证据口径；最终应用继续由既有人工批准门控制。

## 非阻断观察

1. 真实模型用例保持显式 opt-in，避免 CI 误用私有模型或重复消耗；阶段验收依赖单独保存的真实 smoke artifact。
2. `createOrResume` 当前先检查受信启动可用性，再查看进程内幂等缓存；正常重启路径由持久恢复库接管。广泛生产启用前可再评估瞬时安装不可用时的同请求回放语义。
3. 固定 OMP 的 `write` envelope 在公开权限事件中按写入型 `edit` 处理，安全边界一致，但未来若 UI 要区分“创建”和“编辑”，应增加安全枚举而不是暴露原始消息。
4. 私有布局测试属于固定路径契约测试，不能替代生产装配和受信启动测试；后两者已有独立覆盖。
