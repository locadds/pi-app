# ADR：Pi 原生、Skill 与插件优先

- 状态：已批准，仓库级强制前提
- 日期：2026-09-02
- 适用范围：小规 Agent 的所有新功能、能力扩展、文档处理、工具与框架改动
- 决策入口：仓库根 `AGENTS.md`

## 背景

小规基于 Pi Native Coding Harness。Pi 已提供 Resource Loader、Skill、Extension/Package、Agent Loop、工具调用与附件引用等通用能力。若小规在框架层重新实现能力发现、意图判断、工具调度或插件机制，会增加重复状态、Prompt 硬编码、维护成本和与上游脱节的风险。

用户于 2026-09-02 明确确认：能由 Pi Skill 解决的问题不修改框架；能由 Pi 插件解决的问题同样不修改框架；每个功能开发前必须先搜索 Pi Skill 与插件。

## 决定

所有功能使用同一复用门：

```text
需求
  ↓
Pi 原生能力
  ↓ 不满足
Pi Skill
  ↓ 不满足
Pi 插件 / Extension / Package
  ↓ 不满足
已批准的成熟开源或院内能力
  ↓ 仍有已验证缺口
最小适配或框架修改
```

候选能力能够完成真实任务时，工作内容收敛为选型、必要适配、固定版本、安装包装配和验收；不再开发同类框架功能。

## 每个功能开始前的必做检查

1. 实查当前锁定 Pi 版本的原生接口、Resource Loader、内置工具和附件行为。
2. 检索当前已安装 Skill、可引入 Skill、Pi 插件及 `pi.dev/packages` 候选。
3. 对最接近的候选执行最小真实任务冒烟，核对输入、输出、错误模式、离线性和 Windows 可用性。
4. 在计划、工作单或 `DEVELOPMENT_STATUS.md` 中记录候选来源、固定版本/commit、测试结果和采用或拒绝理由。
5. 候选满足需求时，直接进入集成与安装包验证；候选不满足时，先判断能否通过 Skill 编排或声明式插件适配补齐。
6. 只有留下可复核的能力缺口后，才进入最小框架方案与人工批准。

“没有搜索”“只看名称”“只读 README”“模型认为不适合”均不构成框架开发依据。

## Skill 与插件的职责

- Skill 向模型说明何时使用、如何组合现有工具、输入约束、失败处理和完成标准。
- 插件/Extension/Package 提供可复用工具或流程；桌面展示优先使用既有声明式 Adapter 与通用 Extension UI。
- 模型通过 Pi 原生 Agent Loop 理解用户意图并选择 Skill、插件或工具。
- 工具对真实输入负责：校验格式、权限和安全约束，返回可行动的结构化或明确错误。
- 小规框架只保留企业安全、进程隔离、策略审计、安装包装配以及 Pi 原生确实没有的院内专业接缝。

## 文件与文档能力的应用

文件类型不替代任务意图。同一个 PDF 可能用于读取正文、生成模板整理报告或作为其他任务的参考；模型应根据用户请求与 Skill/工具说明选择能力，各工具再校验其实际接受的文件。

因此：

- 不建设 `WORK-P1-DOCUMENT-TYPE-ROUTING-01` 中设想的中央 PDF/DOC/DOCX 自动路由器。
- 不把通用文件令牌平台或自定义“一次纠错”状态机作为文档功能前置条件。
- 模型选错工具时，优先依靠工具的明确错误和 Pi 原生 Agent Loop 继续判断；只有出现可复现的循环或安全问题后才另立最小修复。
- DOC、DOCX、PDF 等工具继续校验真实文件头和结构，不完全相信扩展名或模型选择。
- PDF 可参与只读模板整理报告；PDF 直接生成可编辑正式 Word 模板不在当前范围。
- 既有专用选择器和私有 handoff 可继续服务已经批准的流程，但不得被无证据扩建成全局文件基础设施。

## 安装包与供应链

采用的 Skill 和插件应通过 Pi 原生加载机制进入产品，并在全新安装、离线启动和升级场景中验证可发现性。第三方项必须记录：

- 官方来源；
- 精确版本、tag 或 commit；
- 许可证与分发条件；
- 所需脚本、二进制和运行时依赖；
- Windows 与离线验证结果。

生产包不在运行时静默下载未固定版本。自编 Skill 与必要脚本随安装包交付；可替换的插件保持 Pi 插件接口，不把其实现复制进小规框架。

## 框架修改例外门

框架修改必须同时满足：

1. 已完成 Pi 原生、Skill、插件和现有适配机制的实查与真实冒烟；
2. 存在明确的产品、安全、合规、离线、进程隔离或确定性专业计算缺口；
3. 缺口不能通过 Skill 编排、插件配置或声明式 Adapter 解决；
4. 方案只修改最小接缝，并保留 Pi 上游升级能力；
5. 用户批准该例外范围。

## 完成标准

Skill/插件方案只有同时满足以下条件才算完成：

1. 干净配置或全新安装能够发现并启用目标 Skill/插件；
2. 模型在真实任务中根据意图选中并调用正确能力；
3. 工具成功路径、格式/权限错误路径均有验证；
4. 绝对路径、敏感正文和内部运行细节遵守对应工具既有安全契约；
5. 安装包包含固定版本的必要资源，来源与许可证可追溯。

## 被取代的旧计划

`DEVELOPMENT_STATUS.md` 中 2026-08-31 登记的“WORK 文档类型识别与能力路由”、中央 PDF/DOC/DOCX 自动路由、统一附件令牌化等内容保留为历史记录，但不再是当前待办或架构方向。本 ADR 与根 `AGENTS.md` 是后续工作的权威前提。
